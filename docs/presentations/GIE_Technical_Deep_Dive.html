Why GIE exists

The gap

AI apps ship with prompts, tools, MCP servers, and cloud bindings — often invisible to risk teams.

What GIE does

Scan → normalize → reason → recommend → validate → explain. One Orchestrator. Human gates when stakes rise.

Outcomes

Context Model, risk/compliance posture, deployable policies, explanations, learning loop, IDE/CI connectors.

Hexagonal / Clean Architecture
  • Adapters → Application → Domain ← Ports ← Driven adapters
  • Domain free of FastAPI / SQLAlchemy / Neo4j / Kafka
  • DDD aggregates + CQRS + outbox → Kafka
  • Shared: gie-contracts, gie-observability, gie-security
